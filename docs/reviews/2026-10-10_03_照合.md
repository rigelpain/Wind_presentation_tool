## 責任者に戻す理由

指示書 4節の side の `left` / `right`（片方を幅のおよそ 70%、もう片方をおよそ 25%）と、同じ節の「ワイプが出ているあいだは画像の領域を上から 720px までに収める」が、横長の写真では両立しない。作業員は両方を文字どおり守っている。それでも、題（heading）があると `left` にしても左の写真が大きくならない。

- 題があると画像の領域の上端は 273px（題 56〜142px、札 200〜261px）、下端は 720px。高さは 447px が上限になる
- `both` の左の箱は 840×447px、`left` の左の箱は 1210×447px。4:3 の写真はどちらも高さで決まり、**596×447px で同じ大きさ**（`03_compare_side_both.png` と `03_compare_side_left.png`）。16:9 でも 795×447px で同じ。変わるのは、右が 432px 幅に縮むことだけ
- ワイプを隠す（H）と下端が 1016px になり、`left` の左の写真は 991×743px に大きくなる（`03_compare_side_right_wipe_hidden.png` は right の例）

指示書 2節の「片方だけ拡大する」を、ワイプが出ている授業の場面で満たすには、完成の条件を決め直す必要がある。たとえば次のどれか。決めるのは責任者。

1. `left` / `right` のときは 720px の制限を外す（大きい方はワイプの上にかかってよい）か、その段階ではワイプを隠す前提にする
2. 「大きく」を幅ではなく高さで決める（その段階だけ札や題を小さくして、画像の高さを広げる、など）
3. 横長の写真では `left` / `right` を使わない運用にする（授業の中身で避ける）

このほかの条件はすべて満たしている（下の照合表）。上の点が決まるまで、差し戻しはしない。

## 確かめ方の記録

- 型と組み立て・計算: 01 と同じ
- 画面: headless の Chromium（CDP、1920×1080・縮尺 1）。写真は試しの画像を `putPhoto` で入れた。静止画はカメラが使えないので、`src/media/snapshots.ts` の `setSnapshot` で名前入りの画像（B-full / B-A / B-B、A-full / A-A / A-B）をメモリに入れ、出し分けを読んだ。確かめたあとは `clearSnapshots()` で消した
- 大きさ: `getBoundingClientRect()` を舞台の縮尺（1）で割った値。写真が箱の中でどの大きさになるかは、箱の大きさと写真の縦横比（4:3）から計算し、撮った絵で照らした
