# 指示書: コントロール画面「カメラ・ワイプ」の枠

- 日付: 2026-10-11
- 案件: プレゼンツール
- 作成: 本社（開発の責任者の代行）
- 先に読む: `docs/briefs/10_コントロール画面_共通.md`、`src/wipe/bus.ts`（`useCameraRemote`）、`src/wipe/CameraSetup.tsx`（表示画面の中のカメラの準備。見本として）

## 1. 納品物

`src/control/CameraPanel.tsx`（＋`CameraPanel.css`）。export `CameraPanel`（props なし）は変えない。

## 2. 前提

カメラと顔の追尾は**表示画面の窓で動く**。コントロール画面からは `useCameraRemote()` で操作し、表示画面から届く状態（`status`）と確認用の絵（`preview`、objectURL）を出す。`status` が `null` のときは表示画面が開いていない。

## 3. 中身（上から）

1. **確認の絵**: `preview` があれば `<img>` で幅いっぱい（16:9 の箱）。なければ箱に文言:
   - `status === null`: 「表示画面が開いていません」と「表示画面を開く」ボタン（`openDisplay()`、`src/control/Control.tsx` から import）
   - `status.status === 'idle'`: 「カメラは止まっています」
   - `'starting'`: 「カメラを起動しています…（表示画面にカメラの許可が出たら、表示画面で許可してください）」
   - `'error'`: `status.error`
   - 絵の下に小さく「検出 {faces} 人 / {fps} fps」と、2人それぞれの「見失い中」（`status.lost.A` / `B`。A＝登録したときの左の人＝進行、B＝右の人＝解説。ただし `state.wipe.swapped` が true なら逆）
2. **カメラ**: 選択欄（`status.devices`、いまの値 `status.deviceId`、「既定のカメラ」= ''）→ 選んだら `start(deviceId)`。ボタン「カメラを始める」（`start()`、動いているときは「始め直す」）、「止める」（`stop()`）。「動画・画像で試す」のファイル選択（`accept="video/*,image/*"` → `sendFile(file)`）
3. **2人の登録**: 説明（「2人ともカメラに映った状態で押します。画面で左に映っている人が『{進行の役割名}』、右の人が『{解説の役割名}』になります」。役割名は `useLesson().roleLabels`）とボタン「登録する」（`register()`）。ボタン「左右を入れ替える」（`dispatch({ type: 'swap' })`、入れ替え中なら ✓）
4. **ワイプの見せ方**: ボタン5つ「2人 / 解説を大きく / 進行だけ / 解説だけ / カメラを隠す」→ `dispatch({ type: 'wipe', mode })`。いまの `state.wipe.mode` のボタンに `className="is-on"`。キーの手がかり（E・H・W・S）を小さく
5. **ワイプの大きさと寄り**: スライダー2つ
   - 大きさ: `state.settings.wipeScale`、0.6〜1.6、刻み 0.05 → `dispatch({ type: 'settings', patch: { wipeScale } })`。値を「×1.00」の形で横に
   - 顔への寄り: `state.settings.wipeZoom`、0.6〜1.8、刻み 0.05 → `patch: { wipeZoom }`
   - 「標準に戻す」ボタンで両方 1 に
6. **表示**: チェック2つ「鏡のように左右を反転して映す」（`state.wipe.mirror`、`dispatch({ type: 'mirror' })`）、「ワイプに役割名を出す」（`state.wipe.showLabels`、`dispatch({ type: 'labels' })`）
7. 最後に小さく「顔の映像はこのPCのブラウザの中だけで使い、保存も送信もしません」

## 4. 触ってよいファイル

`src/control/CameraPanel.tsx`、`src/control/CameraPanel.css` だけ。

## 5. 完成の条件

1. tsc と vite build が通る
2. 上の 1〜7 がそろい、それぞれ書かれた関数か action を呼ぶ
3. `status` の4つの状態と `null` で、確認の絵の箱の文言が上のとおりに変わる
4. 見失い中の表示が `swapped` を考えて役割名と合っている

## 6. 妥協しない点

- 確認の絵を保存したり、外へ送ったりしない（`<img>` で出すだけ）
