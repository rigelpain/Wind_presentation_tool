## 1. 納品物

`src/scenes/CompareScene.tsx`（＋`CompareScene.css`）: 場面「compare」。仮の部品を置き換える。

## 2. 何に使うか

- 元の紙と一目で分かる版、変化の前後、上位と下位の紙を、左右に並べる。片方だけ拡大する
- 変化盲の答え合わせ: カメラを隠す前と後の静止画（エンジンが自動で撮ってメモリに置く）を並べる
- 前後の切り替え（成果物の前と後）
- フリッカー: 2枚を、短い黒を挟んで交互に映す

## 3. props

`SceneKind` の `steps` は、side なら `(p.steps ?? ['both']).map(() => [])`、toggle と flicker なら `[[], []]`。

```ts
interface CompareItem {
  src?: string;                         // public/ からのパス
  slot?: string;                        // 写真の読み込み（U）で入れた写真の枠
  snapshot?: 'before' | 'after';        // カメラを隠す前・後の静止画
  role?: 'host' | 'guest' | 'full';     // snapshot のとき、誰の切り出しか。既定 'full'（カメラ全体）
  caption?: string;
}

interface CompareProps {
  heading?: string;
  left: CompareItem;
  right: CompareItem;
  labels?: [string, string];            // 左右の札。例 ['前', '後']
  mode?: 'side' | 'toggle' | 'flicker'; // 既定 'side'
  steps?: ('both' | 'left' | 'right')[];// side の段階ごとの見せ方。既定 ['both']
  flickerMs?: number;                   // flicker で1枚を映す時間。既定 800
  gapMs?: number;                       // flicker の黒の時間。既定 250
}
```

## 4. 見せ方

- **画像の出し方**: `src` / `slot` は `basic.tsx` の `MediaView` に `{ src, slot, fit: 'contain' }` を渡して出す。`snapshot` は `useSnapshots()` の `before` / `after` から、`role` が `full` なら `.full`、`host` / `guest` なら `trackOf(role, state.wipe.swapped)` で `'A'|'B'` を得て `.A` / `.B` を `<img>` で出す。ないときは「静止画がまだありません（カメラを隠して戻すと自動で撮ります）」を 36px 以上で出す
- **side**: `steps` の段階ごとに
  - `both`: 左右に同じ大きさで並べる（間 48px）
  - `left`: 左を大きく（幅のおよそ 70%）、右を小さく（およそ 25%）
  - `right`: その逆
  - 大きさの変化は 0.5 秒（`var(--move)` `var(--ease)`）
  - 段階の数は `steps` の長さ。演出の記録はしない（どの段階も `[]`）
  - 札（`labels`）は各画像の上に 44px 以上の太字。`caption` は画像の下に 36px 以上
- **toggle**: 段階が2つ（`[[], []]`）。段階0で左だけを全面に、段階1で右だけを全面に。切り替えは 0.5 秒の重ね（クロスフェード）。札・説明があれば出す
- **flicker**: 段階が2つ（`[[], []]`）。段階0は左を全面に止めて出す。段階1で `stepAt` から「左 `flickerMs` → 黒 `gapMs` → 右 `flickerMs` → 黒 `gapMs`」を繰り返す。今どれを出すかは経過時間から計算する（setInterval の積み重ねにしない）。描き直しは `useNow(30)` 程度。`flickerMs` が 300 未満、`gapMs` が 80 未満のときは、それぞれ 300・80 に引き上げる（速い点滅を作らないため）
- ワイプ（左下・右下、高さ約 320px）: side と toggle は、ワイプが出ていても画像の大事なところが隠れないよう、画像の領域を画面の上から 1920×1080 の座標で 720px までに収める。ただし `state.wipe.mode === 'hidden'` のときは全面（下の余白 64px）を使ってよい。flicker は全面
- **【2026-10-10 改め（照合 03 を受けて）】** 上の「720px まで」は、side の `both` と toggle に当てる。side の `left` / `right` では、**大きくする方の画像**は画面の上から 1016px まで使ってよい（ワイプが画像の角に重なってよい。1枚をよく見せるための段階なので、大きさの変化が見えることを優先する）。小さくする方は 720px までのまま

## 6. 完成の条件

1. `npx tsc --noEmit` と `npx vite build --outDir /tmp/wind-check-03` が通る
2. side / toggle / flicker の3つが上のとおりに出る。`steps` が上のとおり
3. snapshot の `role` ごとの出し分け、ないときの文言
4. flicker の「経過時間 → 左 / 黒 / 右」を決める関数を切り出し、flickerMs=800・gapMs=250 で経過 0・799・800・1049・1050・1849・1850・2099・2100 ms の結果（左 / 左 / 黒 / 黒 / 右 / 右 / 黒 / 黒 / 左）を node で確かめて報告に書く。flickerMs=100 を渡したとき 300 に引き上がることも確かめる
5. ワイプとの重なりの決まり（上から 720px まで）を守る

## 7. 妥協しない点

- 顔が写る静止画は、`snapshots.ts` のメモリから読むだけ。保存（localStorage、IndexedDB、ダウンロード）や送信をしない
- 時間は `stepAt` 起点
